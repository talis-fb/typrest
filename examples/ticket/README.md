# Ticket example project

An event ticket on a custom 210 x 90 mm page, with a QR code generated by a pinned Typst Universe
package.

```text
typrest.toml
templates/
  ticket/                  # template ID and route: POST /ticket
    main.typ
    schema.yml
    payload.json           # sample request body
```

## Run it

This project imports `@preview/tiaoma:0.3.0`, so the first `check` or `serve` needs network access
to download it into `.typrest/packages` (git-ignored). Later runs and all render requests use the
local cache. See [Template layout](../../docs/specs/templates.md) for package rules.

```bash
cd examples/ticket
typrest check
typrest serve --watch
```

```bash
curl -X POST http://localhost:8080/ticket \
  -H 'content-type: application/json' \
  --data @templates/ticket/payload.json \
  -o ticket.pdf
```

## What it demonstrates

- **Custom page size**: `#set page(width: 210mm, height: 90mm, margin: 0pt)`.
- **Pinned package**: `qrcode` from `@preview/tiaoma:0.3.0` encodes `qr_payload`. The version is
  literal and fully pinned.
- **Defaults**: `holder.seat` defaults to `""` (shown as "General admission") and `price` defaults to
  `0` (shown as "Free"), so the template never branches on missing keys.
- **Explicit `null`**: a default never replaces an explicit `null` (`REQ-SCH-081`), and `null`
  continues through type validation (`REQ-SCH-033`). Because `seat` is `type: string`, `"seat": null`
  is rejected with a 422 before the template runs, so the template never sees `null`. Omit the
  field to get the default.
- **Warm-up compile**: the startup compile uses a schema-seeded payload where `qr_payload` is
  `""`, which the QR encoder rejects. The template draws an empty box for an empty value
  instead of failing.

## Invalid payload

`"seat": null` (here with the other required fields present):

```bash
curl -i -X POST http://localhost:8080/ticket \
  -H 'content-type: application/json' \
  -d '{"event":{"name":"Open Air Cinema","date":"2026-12-01","venue":"City Park"},"holder":{"name":"Sam Example","seat":null},"ticket_id":"OAC-1","qr_payload":"OAC-1"}'
```

Response: `422` with

```json
{"error":"schema_validation_failed","message":"Payload validation failed","violations":[{"field":"$.holder.seat","issue":"expected type string, got null"}]}
```

Removing the `seat` key renders a "General admission" ticket with status `200`. See the
[HTTP API specification](../../docs/specs/http-api.md) for the error envelope.

## Customizing

Edit the colors at the top of `main.typ`, change the currency symbol in the `price` expression, or
use a different symbology from `tiaoma` (for example a `code128` barcode) for the stub.
